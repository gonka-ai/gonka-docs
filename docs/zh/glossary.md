# 词典

**AI Token** 是一种模型特定的计算单位，用于量化训练或推理操作所需的计算成本。例如，在 QwQ-32B 模型（FP16，32K 上下文）的背景下，一个 AI Token 可能代表处理固定数量输入和/或输出标记所需的资源。AI Token 与基础模型的特性紧密相关，反映了实际的内存、FLOP 等资源消耗。

**抵押** 机制允许参与者锁定 GNK 代币，以激活其已获得的部分计算证明（PoC）权重。投票权绝非仅通过持有代币获得。GNK 代币作为经济抵押品，而非影响力来源。影响力通过持续的计算贡献获得，而锁定 GNK 抵押品是参与治理并确保问责制的必要条件。

**确认/随机计算证明（cPoC）** 是一种辅助验证机制，用于在主要的[计算证明](https://gonka.ai/glossary/#glossary:~:text=Proof%20of%20Compute%20(PoC)%20is,is%20the%20execution%20phase%20of%20PoC.)（PoC）冲刺阶段之外验证主机声明的计算权重的稳定性。这些检查旨在确认主机持续提供与其最近 PoC 结果相符的计算能力。cPoC 不替代标准的 PoC 流程（冲刺）。

**确认率** 是主机在 PoC 阶段得出的周期权重与 cPoC 阶段获得的权重之间的比率。较高的确认率表明主机提供的计算更加稳定。如果确认率低于或等于 50%，主机将被取消获得周期奖励的资格。

**共识** 是网络就区块链的单一可验证状态达成一致的协议，确保所有参与者维护一致且防篡改的账本。在 Gonka 中，共识通过 PoC 实现。

**周期** 是链的核心运行周期。在周期内，主机执行有意义的 AI 工作、参与验证并累积奖励。一个周期持续 15391 个区块（约 23 小时），并在通过确定下一周期的主机权重完成一次冲刺后结束。

**Gonka 区块链** 是去中心化 AI 网络的基础账本和协调层（L1）。它记录余额、交易和加密工件，以证明主机正确执行了 AI 工作，而所有实际计算（如推理和训练）均在链下进行。

**Gonka 网络** 是一个由参与者（包括主机和开发者）组成的综合生态系统，通过去中心化基础设施进行交互。依托 Gonka 区块链，该网络分发任务、验证结果，并仅奖励可验证的有用工作，从而为 AI 工作负载创建一个竞争性且可扩展的环境。

**Gonka 角色：**

- **开发者** 利用网络的分布式计算能力构建和部署 AI 应用程序。
- **贡献者** 参与核心区块链代码库、协议升级、性能优化、安全补丁和新功能集成的开发。参见[悬赏计划](bounty-program.md)。
- **持有者** 持有网络的原生代币，仅意味着拥有一个包含代币的 Gonka 钱包。持有者可以持有、转账或出售代币，用于推理并按照协议规则使用它们。成为持有者不意味着除标准代币所有权外的任何义务、责任或治理角色。
- **主机** 向网络贡献计算能力。主机执行推理和其他计算任务，并根据其贡献的计算能力按比例获得奖励，前提是保持诚实参与和可靠性。主机是网络的支柱。只有主机在网络中拥有投票权。此投票权代表其在治理中的权重，用于提议和投票决定协议决策、参数变更和升级。任何主机均可充当验证者、转账代理和执行者（这些并非预定义或链上角色，而是在处理推理请求时动态承担的操作功能）。

**ML 节点** 在 Gonka 中是主机私有基础设施内的一个计算节点，负责执行所有真实的 AI 工作负载（如 LLM 推理、训练步骤和冲刺计算）。它不直接与公共网络交互；而是从主机的 API 节点接收任务，并将结果返回给主机。ML 节点在链下执行所有繁重计算，而区块链仅记录验证工件、证明和任务承诺。

**网络节点** 是处理所有通信的服务，包括：

- [**链节点**](https://github.com/product-science/inference-ignite/tree/main/inference-chain) 连接到区块链，维护区块链层并处理共识。
- [**API 节点**](https://github.com/product-science/inference-ignite/tree/main/decentralized-api) 作为区块链（链节点）与 AI 执行环境（ML 节点）之间的主要协调层。它提供 REST/gRPC 端点，用于与用户、开发者和内部组件交互，同时管理需要链下执行的工作编排、验证调度和结果验证流程。除了处理用户请求外，它还负责：
    - 将推理和训练任务路由到 ML 节点
    - 记录推理结果并确保任务完成
    - 调度和管理验证任务
    - 向链节点报告收据和签名以达成共识
    - 编排 PoC

**私钥** 是加密密钥对的私有组成部分，对于保障和授权 Gonka 网络中的交易和操作至关重要。私钥必须始终保密。任何获得私钥的主体均可代表其所有者在协议层面执行操作。保护私钥是密钥持有者的唯一责任。

**计算证明（PoC）** 是一种共识机制，以可证明的基于 Transformer 的计算能力取代基于资本或哈希的权重。它定义了如何测量真实 AI 计算并将其转换为治理和共识权重。PoC 通过每个周期末尾进行的短时同步冲刺执行。在冲刺之外，周期用于实际的 AI 计算。实践中，“PoC”和“冲刺”这两个术语常互换使用。当提及“下一个 PoC”或“PoC 阶段”时，通常指下一个冲刺，即 PoC 的执行阶段。

**公钥** 是公开可用的加密密钥，用于验证签名、加密消息以及在 Gonka 网络中识别账户。这是加密密钥对中可公开共享的部分。

**随机任务验证** 是平台验证策略的基础。系统并非冗余验证每个推理任务，而是根据主机（执行者）的声誉随机选择一部分任务进行验证。主机声誉越高，其工作所需验证的比例越低。这种方法将开销大幅降低至仅 1–10% 的任务，同时通过概率保证和作弊被发现时失去奖励的威胁维持信任。

**冲刺** 是 PoC 的一个阶段。在冲刺期间，所有主机同时在具有随机层的 Transformer 模型上对一连串非ces 执行 AI 相关推理，生成输出向量。主机在下一周期的权重与其处理的非ces 数量成正比，前提是报告的输出可被证明由所需的冲刺模型生成。治理投票权使用权重上限，该上限不得超过该权重。

**冲刺种子** 是基于最新区块链状态的随机数生成器生成的。此种子用于对 Transformer 模型的隐藏层应用随机变换。

**验证者 `status: jailed`** 表示由于未能满足最低共识参与要求（具体而言，在定义的时间窗口内签署的区块数量少于所需数量），验证者已被协议自动且暂时移除出区块生产。

**权重** 是主机在一个周期内的实际、完全调整的计算贡献。它由计算证明得出，并根据确认、惩罚、抵押和 30% 的集中度限制进行调整。权重用于奖励、确认、定价和任务选择。从 v0.2.16 开始，治理投票权使用权重上限而非权重。参见[什么是权重？](FAQ.md#what-is-weight)。

**权重上限（`CapWeight`）** *(v0.2.16)* 是主机的信任权重：`min(Weight, confirmed weight from the previous epoch)`，然后进行集中度限制，确保任何主机持有的总 CapWeight 不超过 30%。从 v0.2.16 开始，它用于治理投票权、BLS 阈值签名和 PoC/cPoC 验证投票。上一周期未在线的主机在下一周期的 `CapWeight = 0`，但仍根据权重获得奖励。前一周期的上限与 30% 的集中度限制不同：该限制首先应用于权重，然后再次应用于生成的 CapWeight。参见[什么是权重上限？](FAQ.md#what-is-the-weight-cap)。

**投票权** *(v0.2.16)* 是主机在治理和共识关键投票中的影响力。从 v0.2.16 开始，它等于权重上限（`CapWeight`），而非权重。权重本身仍是奖励的来源。
